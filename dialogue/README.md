# 台詞台帳（dialogue/）

ゲームの会話の**唯一の正本**。ビルド時に `vite.config.ts` の `dialogue-ledger` プラグインが読み、`virtual:dialogue` として配る。書式違反はビルド失敗（該当ファイルと id を表示）。仕組みの経緯は Issue #29、実装は #74、保存は `docs/save-data.md`、設定は `docs/story.md`。

ここにある `*-sample-NN` は動作確認用の実例で、本制作ではない（本制作は量産の型で行い、置き換える）。

## ゲームでの使われ方

再生は `src/hooks/useSubtitle.ts`、選択は `src/utils/dialogueEngine.ts`、時間などの設定値は `src/utils/gameConfig.ts` の `DIALOGUE_CONFIG`（開始待ち 4 秒、雑談の間の無言 30 秒、中間コメント 240 秒）。優先順位は フラグ会話 > 誤報 > 出現ヒント > ノルマ到達 > 特殊条件 > 中間コメント > 雑談。出現ヒント（#343）は、異変が未報告のまま `DIALOGUE_CONFIG.hintDelayMs`（既定 45 秒のプレイ時間）経つと、`hintMinGapMs`（既定 20 秒）のプレイ時間ごとに「機会」が回ってきて、機会ごとに確率 `hintChance`（既定 0.5）でその異変の `spawn-hints.yaml` の会話を1件出す（外れたら次の機会まで待つ。乱数は機会ごとに1回）。誤報用の `anomaly-lines.yaml` とはプールが別で、使用済みにならず、同じ異変に未報告のあいだ何度でも出る（直前にその異変で出した案は、他に案があれば避ける。保存データには何も書かない）。出す直前に未報告かを確認する。当たりの機会に別の会話が表示中などで出せなかった場合、その当たりは次の機会に持ち越さず捨てる（実効の確率は `hintChance` よりわずかに低い。意図）。ヒントの会話はすべて `tone: serious` なので、出た直後は `seriousQuietMs`（20 秒）の間、雑談が抑えられる（仕様）。表示が始まったヒントは、途中で報告されても最後まで出す（途中で切ると不自然）。その後は出ない。案が無い異変には出さず、共通の誤報会話には落とさない。ヒント同士は最短 `hintMinGapMs`（ウォール時計）空け、表示中の会話には割り込まず次の pick で出る。`seriousQuietMs` は受けず、誤報と同じく割り込みやすい（一貫性のため）。`hintEnabled: false` で全体を切れる。ヒント用の台詞は「お手つきをした前提」にしない（まだ何も間違えていない）。ヒントの強さは台詞しだい（942通りの本番稿は画面内の位置まで。何が変わるかは言わない）。誤報は即座に、フラグ会話は表示中の字幕の直後に割り込む（中断された会話の残りは捨てる）。ただしフラグ会話の最中は誤報も別のフラグも割り込まず、待たせる。会話は最初の1行が画面に出た時に使用済みになる（出る前に割り込まれた会話は使われない）。中間コメントも実際に再生した時に済みになる。`closing` の `ending` 台詞は、`child` フラグ成立後に新たに発生した異変を一件も報告せず時間切れになった時に再生され、同時に画面が `public/images/ending-bar.webp`（1か月後のバー）に切り替わる（判定は `src/utils/endingJudge.ts`、Issue #86。令和の印（`REIWA_IDS` が空、#83）が入るまで `child` は通常プレイでは立たず、ending には到達できない（テストと localStorage への手動注入でのみ確認できる）。`final` フラグは使わない。撤収は ending にならない）。

### ノルマと特殊条件の会話（#428）

ゲームの規則は変えず、**台詞の選び方だけ**がノルマ（`minCorrectReports`、正解の報告 4 件）と、そのシフト内の状態に反応する。

- **終わりの会話**: `closing` の `dawn` と `withdraw` は `when.quota: met | unmet`（終了の瞬間にノルマを満たしていたか）を必ず持ち、条件ごとに**別の抽選袋**になる。`ending` は `quota` を持たない（付けるとビルドが落ちる）。
- **誤報**: `false-report.yaml` の `when` なしはノルマ前、`when: { quota: met }` はノルマ達成後のお手つき。達成後も、**その異変の未使用の `anomaly-lines`（ヒント入り）を先に出し**（ヒントは次を見つける助けになるので、達成後も捨てない）、使い切った・無い時に後者の専用の袋から引く（袋が無ければ従来どおり）。撤収（3 回目）は `closing` の `withdraw` × `quota: met`。
- **ノルマに届いた瞬間**: `quota-reached.yaml`（`when` なし）。正解の報告が `minCorrectReports` に**ちょうど届いた時に 1 シフト 1 回だけ**、直後に出る（出現ヒント・誤報の次。`useSubtitle` が数の増え方を見て判定するので、途中から始まったシフトで過去の分は数えない）。確率では間引かない。台詞は「今ので」のように直前の出来事を指さない（出るまでに少し遅れることがある）。
- **特殊条件**: `situation.yaml`、`when: { situation: hot | cold | brink | tenth }`。`hot`=調子がいい（`hotWindowMs` 内に `hotCount` 件、または誤報なしで `hotCleanCount`（5）件目。Issue #428 の「誤報なしで 4 件以上」より 1 つ遅い: 4 件目はノルマに届く find で、その一言と重なるため hot にならず、4 では実ゲームで一度も起きないから）、`cold`=`coldAfterMs` の間何も見つけていない、`brink`=誤報があと 1 回で撤収、`tenth`=そのシフトで 10 件目。判定は `src/utils/situation.ts`（純関数、乱数は注入）、設定は `DIALOGUE_CONFIG.situations`（仮値）。**字幕の頻度を上げない**ために、(1) 機会ごとに条件別の `chance` で 1 回だけ振る（外れた機会は持ち越さず、使用済みにもしない）、(2) 出る時は次の雑談の枠を使う（追加の字幕ではない。`chatterIntervalMs` の間隔と `seriousQuietMs` の対象）、(3) 同じ条件は `minGapMs` 空け、1 シフト `maxPerShift` 回まで、(4) 待てる枠は1つで、重要度順（brink > cold > hot > tenth）に上書きされ、待つあいだ `expireMs` を過ぎたら捨てる。(5) ノルマに届いた find と同じ判定では hot を出さず、すでに待っている hot も捨てる（達成の一言と続けて出さない）。`brink` の台詞は緊張を出すため `tone: serious`。
- **抽選袋と使用済み**: 上の条件ごとの会話は、雑談・中間コメントと同じ `drawFromBag`（まだ出ていないものから等確率、一度出たら袋が空になるまで出ない、空になったらその袋だけ補充して直前を避ける）。使用済みは `usedChatter` に入り、シフトをまたぐ（`docs/save-data.md`）。使用済みになるのは最初の 1 行が出た時。
- **通り数の下限**（`DIALOGUE_COUNT_RULES`、`src/utils/dialogueLedger.ts`）: dawn×met 10、dawn×unmet 10、withdraw×met 5、達成後の誤報 8、ノルマ到達 5、特殊条件は各 5。下回ると**ビルドと `npm run check:dialogue-counts` が落ちる**（CI に入っている）。同じ条件の通りは、書き出し・語尾・話者の順・長さ（2〜4 行。`withdraw` の既存 20 通り（未達）は 1 行だが、達成後の 6 通りは 2〜4 行・話者混在）を揃えすぎない。`check:dialogue-counts` が条件ごとに書き出しと語尾の種類数と繰り返しの多いものを報告する。

## 1通りの形

```yaml
dialogues:
  - id: chatter-sample-01
    tone: light # light | serious
    when: { ... } # 種類ごと（上の表）。「なし」の種類では書かない
    unlock: elder1 # 任意。指定フラグ成立後に候補へ加わる（whenとは独立）
    lines: # 1通り＝2〜4行を想定
      - { who: M, text: '昨日の特番　見ました?' } # who: A（刑事）| M（若い男）
      - { who: A, text: 'いや　興味ないから' }
```

- 通常の会話は2〜4行。`closing` の `ending` だけは、1か月後のバーで自動進行するエンディング会話劇として長い1件にまとめる。
- `id` はファイル全体で一意。接頭辞は種類で決まる: `opening-` `closing-` `midpoint-` `chatter-` `story-` `false-report-` `quota-reached-` `situation-`、異変ごとは `an-<異変id>-`（例: `an-AR-01-notice-sample-01`）、出現ヒントは `spawn-hint-<異変id>-`。末尾は連番（実例は `sample-NN`）。
- `tone`: `serious`（フラグ会話・誤報のヒント・深刻な中間コメントなど）の直後は、一定時間（既定20秒）雑談を出さない。何が `serious` かは台詞ごとの印で決める。雑談は `light` のみ（ビルドで検証）。
- `who`: `A` = ベテラン刑事（おばさん）、`M` = 若い警備員。画面に話者は出さず、口調で見分けさせる。

## 字幕規約（ビルドで検証）

- 句読点（、 。 と半角・全角のカンマ／ピリオド）を使わない。
- 区切りは**全角スペース**。半角スペース・改行・タブは使えない。行の前後の全角スペースは削らずそのまま残る。
- 全角スペースは**折り返し位置を決める文節の区切り**でもある（#323）。画面では区切りの間でだけ折り返し、1つの区切りの中では折らない。1行は約16〜18文字なので、**1つの区切りは `src/utils/subtitle.ts` の `MAX_PHRASE_CHARS` 文字以内**にする（数字の正本はそこ。超えるとテスト `dialoguePhrases.test.ts` が落ちる）。長い台詞は意味の切れ目（「を」「は」「に」「も」の後、「〜てから」の後など）で全角スペースを足す。足したあとの `npm run check:subtitle` は、全台詞を実ブラウザ（Chromium のみ確認。フォントは機械依存）で流して、区切りの途中で折れた行・最後の行が2文字以下の行・行頭に小さい仮名や「ー」が来る行が0であることを確かめる。
- **！？と数字は全角**（#334 #352）。半角の `!` `?` と半角数字 0-9 は使えない（ビルドとテストが落ちる）。`…` は使える。数として使う語は全角数字（０-９）にする: 「２人目」「３人とも」「５分」「１つずつ」「１か月」。「もう一度」「もう一回」「一緒」「一瞬」「一部」「一面」「四角」「三角」「三輪車」や「〜を一度見て」「一歩前へ」「最後の一口」のように語・慣用で使う漢数字は漢数字のまま。回数でも「一度」「一歩」「一口」「一瞬」など慣用の語は漢数字のまま（「一回」「一杯」「一本」「一つ」など助数詞は全角数字）。「一段落とす」のように全角数字だと読み違える語も漢数字のまま。英語 `en` は半角の `?` `!` と半角数字でよい。
- 既存の台詞を直したときは `node scripts/fullwidth-ja.mjs`（半角→全角と「数＋助数詞」の漢数字→全角数字を機械的に直す。再実行しても変わらない。`--check` で未変換があれば1で終わる）。新しく書いた台詞は最初から全角で書く。
- 実在の番組名・商品名・人物名・商標は使わない（伏せるか架空名）。

## 英訳（`en`、Issue #326）

字幕の英訳は、台詞の1行に任意項目 `en` を足して書く。`en` の無い行は日本語のまま出る。

```yaml
lines:
  - {
      who: A,
      text: '昨日の特番　見ました?',
      en: "Did you watch last night's special?",
    }
  - { who: M, text: 'いや　興味ないから' } # en なし = 日本語のまま
```

- `who` と `text`（日本語）は今のまま変えない。`en` は同じ行の英訳で、行の数・順序は日本語と1対1。
- **書き方**: 英語は通常の句読点（, . ? ! ' など）を使ってよい（日本語の「句読点なし」規約は英語には掛からない）。半角スペースで単語を区切る。**全角スペース・改行・タブは使えない**（ビルドが落ちる）。文字列は空にできない。YAML では `'` を含むなら `"..."` で囲む。
- **口調**: `A` = ベテラン刑事（おばさん）。くだけて世話焼き、ずけずけ言う。`M` = 若い警備員。丁寧だが頼りなく、素直。日本語の口調の差を英語でも保つ（画面に話者は出ないので、口調だけで見分けさせる）。
- **折り返し**: 英語は文節で折らず、通常の単語折り返し（画面の `.seg` 処理は日本語専用）。長さの上限検査（`MAX_PHRASE_CHARS`）は日本語だけで、英語には掛からない。英語で字幕が長くなった時の大きさ・行数の確認は、翻訳が入ってから別途行う。
- **長さの目安**: `en` は `src/utils/subtitle.ts` の `EN_GUIDE_CHARS` 文字以内を目安にする（長いと小さい画面で3行を超え、カメラ番号に届く）。超える場合は意図して確認する。`npm run check:subtitle-en` が超えた行を警告として出す（ビルドは落ちない）。
- **進捗確認**: `npm run check:subtitle-en` が、未翻訳の行数をファイル別と総計で出す（終了コードは常に0。`en` の書式違反があればここでも落ちる）。数字はここに書かず、このコマンドの出力を見る。
- **全体スイッチ**: 英訳が入っても、`src/utils/gameConfig.ts` の `SUBTITLE_EN_ENABLED`（初期値 `false`）が `false` の間は英語環境でも日本語のまま。日本語で十分テストプレイしてから `true` にする（言語方針 2026-11-10）。`true` で、言語が英語（設定の言語、無ければブラウザの言語）かつその行に `en` がある時だけ英語を出す。

## フラグ（`flags.yaml`）

フラグの条件は**ここだけ**に書く（節目の数値を他に書かない）。会話側はフラグ名だけを参照する。1つのフラグの条件はすべて AND で、数値は「以上」。

```yaml
flags:
  elder1:
    foundUnique: 10 # 見つけた異変の数（重複なし。foundIds の長さ。用語は prompts/README.md の用語集）
  child:
    foundUnique: 100
    reiwaFound: 3 # 令和の異変を重複なしで3つ
    requires: [elder3] # 他のフラグが先に立っていること
```

使えるキー: `foundUnique`（重複なしの異変数）、`foundTotal`（重複ありの正解報告数）、`reiwaFound`（令和の異変 = 台帳で `reiwa: true` の `produced` の異変（画像、および出現する画像以外の異変 #77）を、重複なしで何個。印は台帳から自動で決まり、ここには id を書かない）、`loops`（周回数）、`found`（見つけているべき異変 id のリスト）、`requires`（フラグ名のリスト）。定義済みのフラグ名は `elder1` `elder2` `elder3` `child` `childResponse`。`childResponse` は `child` と同時に立ち、直後に短いストーリー会話を再生する。エンディングは累計進行フラグではなく、子供発見後の同一勤務の特殊条件で起動する。節目の数値は**仮の例**で確定ではない（`docs/story.md` 未決）。

`unlock` はすべての会話種類に指定できる任意のフラグ名。`story.when.flag` は「立ったフラグに対応する会話」の指定であり、`unlock` はその会話が候補に入る時期を遅らせる条件。未成立の会話は抽選袋に入らず、使用済みにもならない。成立後は通常の抽選対象になる。未指定なら従来どおり常に候補になる。`flags.yaml` に無いフラグ名を指定するとビルドが失敗する。`loops` 条件のフラグは、周回が終わった次の勤務の開始時に立つ（`foundUnique` `foundTotal` は報告の瞬間に立つ）。
